The most important thing about a password generator: **it must never send your password to a server.**

Any generator that makes an API call to produce your password is a red flag. Every good generator on this list runs entirely in your browser.

## What Makes a Password Generator Trustworthy?

- **Client-side only** — no network requests during generation
- **Uses `crypto.getRandomValues()`** — cryptographically secure randomness
- **Open source** — anyone can audit the code
- **No login required** — accounts create data retention risks

## The Criteria That Actually Matter

### 1. Randomness Source

`Math.random()` is NOT cryptographically secure — it's predictable. Secure generators use `window.crypto.getRandomValues()` (available in all modern browsers). ConvertDox's [Password Generator](/password-generator) uses the Web Crypto API.

### 2. Character Set Control

A good generator lets you choose:
- Uppercase letters (A–Z)
- Lowercase letters (a–z)
- Numbers (0–9)
- Symbols (!@#$%^&*)
- Exclude ambiguous characters (0, O, l, 1)

### 3. Passphrase Support

Random words like `correct-horse-battery-staple` are both memorable and strong. A 4-word passphrase has ~50 bits of entropy — comparable to a random 10-character password.

## Password Length Guide

| Use Case | Recommended Length |
|---|---|
| General accounts | 16+ characters |
| Financial accounts | 20+ characters |
| Master password (password manager) | 30+ characters |
| Wi-Fi password | 16+ characters |

## The Bottom Line

Use a browser-based generator, copy the result directly into a password manager, and never reuse passwords across sites. The generator itself matters less than having unique passwords everywhere.
